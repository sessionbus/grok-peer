# grok-peer v0.5.9

This release requires Sessionbus v0.5.9 (daemon and hub) and pins the Sessionbus Go SDK `v0.5.9`. The version matches core v0.5.9.

**Breaking, a flag day.** The unreleased lane policy field `idle_message` is removed from the protocol and the SDK; message wake is mandatory. This peer requires a v0.5.9 daemon. Peers built with SDK v0.5.7 or earlier are incompatible with it. Upgrade the hub, the host daemons and the product integrations together. Follow the upgrade steps, including the offline lane-row edit, in the [core v0.5.8 release notes](https://github.com/sessionbus/sessionbus/releases/tag/v0.5.8). v0.5.9 has the same runtime as v0.5.8.

This is the first stable release published from this repository. Fixes since the combined v0.5.3 release:
- **ACP request IDs of every valid type are accepted.** String, number and null native request IDs are echoed exactly in replies.
- **Native client requests are answered only by the lane primary.** A native Grok ACP `session/request_permission` no longer ends the managed lane. The lane primary answers it with the non-approval outcome `cancelled` and answers any other well-formed native request with `-32601 Method not found`; the connection stays alive. Observer clients, including the interactive peer observer next to the TUI, leave these requests unanswered, so they cannot deny a prompt shown to the user. Malformed input stays fatal. Nothing is approved and permission policy is unchanged.
- **The alias preflight refuses an incomplete Sessionbus alias.** If the sibling `grok-peer-mcp` alias is missing, dangling or not executable, a managed spawn fails before any native process starts with `Grok Sessionbus integration is incomplete: …`, instead of timing out after about 60 s. The alias is resolved beside the real executable, following symlinks.
- **The interactive launcher retires when its private leader exits.** It terminates the TUI, stops its startup hold and removes its runtime directory, so the presence no longer outlives the leader.
- **A fresh lane's typed `model` is applied.** It is passed to the native `agent` subcommand. Typed `reasoning_effort` and the raw `--agent`, `--no-plan` and `--no-subagents` options are still not applied by native agent mode, and a resumed lane does not receive the typed model.

`scripts/install-grok.sh` installs the latest release by default, so it now installs v0.5.9. Pin `SESSIONBUS_VERSION` on hosts that are not yet in their upgrade window.

## Known limitations

- **Native private-leader respawn.** If the private leader exits while native clients are still attached, native Grok can start a detached replacement leader (`grok agent leader --no-exit-on-disconnect --relay-on-demand`) on the same private socket. It can survive teardown after the private leader exits, and the wrapper does not clean it up; stop a leftover one by its exact PID after confirming its command line. Per Grok source, the replacement runs native auto-update and a fresh lane replayed by the stdio bridge takes its permission mode from `config.toml`. That policy and auto-update risk is source-supported but not observed. See [Private leader loss](../../grok/README.md#private-leader-loss-known-native-limitation).
