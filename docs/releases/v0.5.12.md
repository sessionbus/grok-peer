# grok-peer v0.5.12

This release requires Sessionbus v0.5.9 or newer (daemon and hub) and pins the Sessionbus Go SDK `v0.5.12`. The version matches core v0.5.12. Native Grok is installed separately and is not pinned.

`scripts/install-grok.sh` installs the latest stable release by default, so it now installs v0.5.12 and delivers the changes below, which were previously only on `main`. Pin `SESSIONBUS_VERSION` on hosts that are not yet in their upgrade window.

## Changes since v0.5.9

### Native updates are no longer suppressed
v0.5.9 passed `--no-auto-update` to its private leader and its three native bridges (the TUI never carried it). v0.5.12 passes it to none of them, so they update as native Grok decides.

- **A native update can now replace the private leader during a session.** It can also exit when a newer native client takes it over, or when it is killed.
- **The wrapper does not end the session for that.** The TUI is left to Grok's own reconnect, and a lane's bridge to its bounded native reconnect. Losing the startup hold after the TUI has started does not end the session either.
- **Each such loss is reported on stderr after the TUI exits**, and the launcher exits with the TUI's own status. The TUI's own teardown is not reported as a startup-hold loss.
- **Native behaviour decides the outcome.** Whether the session and its delivery continue correctly after a reconnect depends on the native release.

See [Private leader loss](../../grok/README.md#private-leader-loss-known-native-limitation).

### The Sessionbus helper retires with its launch
After a reconnect, a native replacement leader can keep the session loaded and run its Sessionbus helper after the TUI has gone. The helper now checks its launch every two seconds.

- Once the launcher has quit and removed its private launch directory, the helper ends its Sessionbus presence and exits. The session's row therefore retires a few seconds after `/quit`, not at once.
- A missing socket alone, as during a reconnect, does not end it.
- If native Grok starts the helper again after that, it stays inactive: it offers no Sessionbus tool and publishes no presence.

### Managed lanes
- Lane delivery is bound to the Run it was captured for.

### Sessionbus Go SDK v0.5.12
- **A failed native interrupt is now reported as a failure.** If the wrapper's native cancel fails, the interrupt answers Internal `-32603` "product interrupt failed". Before, it answered a false `{}` success.
  - Within one prompt, a repeated interrupt returns that first result and never sends a second native cancel.
  - In the controlled test (an injected `session/cancel` write failure, 5 of 5 runs), the Run then ended `unavailable` and a later interrupt answered `not_running`.
  - A successful cancel still answers `{}`, and the native terminal decides the outcome.
- The wire protocol is unchanged, so Sessionbus v0.5.9 or newer still suffices.

## Evidence
Nothing was re-run for this release. All evidence is retained from the permanent Linux development host, Sessionbus daemon v0.5.11, one trial per case, with `--yolo` / always-approve only.

- **2026-10-07, grok-peer `f59fdbe`, native Grok 1.0.46.** This build has the SDK v0.5.12 and lane Run binding of this release, and still had the private-leader update suppression. Interactive idle, interactive busy (original task), lane idle, lane busy and lane interrupt with recovery: all PASS.
- **2026-10-09, grok-peer `75c9400a` (the runtime of this release).** A private-leader loss surrogate: a SIGTERM to the wrapper's own private leader, **not an actual native update**.
  - Native reconnected and the session continued.
  - Interactive idle and busy after the reconnect both PASS.
  - The row retired about 3 s after `/quit`, and `config.toml` was unchanged.
  - A native self-update to 1.0.50 happened during that launch, so the TUI ran 1.0.46 and the replacement leader 1.0.50.

The README's installed-validation paragraph describes the earlier v0.5.9 evidence.

## Known limitations
- **No actual update eviction was observed.** The leader-loss evidence is a SIGTERM surrogate. No updater-path parity and no 1.0.50 lane result is claimed; the lane cases ran on native 1.0.46 before the update and helper changes.
- **Native private-leader respawn.** A detached replacement leader (`grok agent leader --no-exit-on-disconnect --relay-on-demand`) can survive teardown, together with an inactive helper. The wrapper does not search for or stop it; stop a leftover one by its exact PID after confirming its command line. Its session-default permission mode for a fresh lane replayed by the stdio bridge comes from `config.toml`.
- **A TUI that ignores SIGTERM keeps the launcher alive.** This is unchanged from v0.5.9: identified from source, not observed live.
- **No macOS live validation**, no default-mode trial, and no repeated-trial or cross-version matrix.
