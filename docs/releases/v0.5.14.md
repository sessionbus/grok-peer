# grok-peer v0.5.14

## SDK 0.5.16 refusal clarification

The Go SDK is pinned directly at v0.5.16. Shared support stays at the actual reviewed common commit `29ddcb4585deaffc637163381ea1bce4a312e237`; the direct SDK requirement selects v0.5.16 over that common revision's older minimum. No product hello, filesystem, cwd, permission or lifecycle mechanism is added.

The SDK reports `unknown_transfer` for a missing local transfer binding and for an ended binding after its existing earlier checks. Existing path, field, role and overwrite checks keep their current precedence and conflict refusals. On a local daemon upgraded to Sessionbus v0.5.16, the SDK's existing hello paths opt in to `unknown_transfer` (-32020) for a status request with no accessible live transfer, including an absent or ended ID. An older daemon keeps `transfer_failed` (-32019); the SDK accepts that legacy answer too. An old daemon can expose the extra hello info key as ordinary public metadata.

The new wire answer applies only to local status replies. Wire Accept/Cancel and federation keep their existing answers. Status still does not return or preserve a completed outcome, file hash or terminal history. A missing final notice does not prove failure or make replay safe. Files are still read and written directly as the OS user, with no sandbox or native approval per path. Tightening transfer permissions later remains OPEN and is not a release gate.

This release requires Sessionbus v0.5.14 or newer on the daemon and every involved hub. It pins the Go SDK v0.5.16 and shared support at `29ddcb4585de`. Native Grok is installed separately and is not pinned. The native plugin's independent version remains 0.5.0.

## File transfers

Managed interactive sessions and lanes expose the shared 18-action Sessionbus tool, including `transfer.offer`, `transfer.request`, `transfer.accept`, `transfer.cancel` and `transfer.status`. Interactive actions use the same admitted SDK Peer and its bound Caller. Lanes use the existing Worker Caller. Offers and final notices use the existing delivery path, with the SDK's local terminal projection before native delivery.

Relative local paths are prefixed with the native session's current roster cwd, or the lane's native launch directory, without cleaning symlink/`..` spelling. With no known absolute base, relative paths are refused and absolute paths remain usable. Local source and destination paths stay at their endpoint rather than going to the daemon or hub.

Transfers use the SDK's direct filesystem access as the OS user. There is no sandbox or native approval per path. Tightening transfer permissions later is OPEN and is not a release gate. The existing Sessionbus tool grant remains; Grok's deny-before-ask-before-allow precedence is unchanged, including an explicit user deny.

Peer shutdown retains the existing SDK-generation and native-work joins. Lost final results and uncertain native submissions are not replayed. This adds no transfer engine, permission layer, retry or durable recovery.

## Previously unreleased changes carried from main

This release also carries the 17 commits already on main after v0.5.12: managed interactive sessions use Grok's own leader rather than a wrapper-created private leader; lanes run one native process with `--no-leader`; lane startup can locate Grok in its own home when the service PATH has none; the typed lane model is named in the native session request; string-ID ACP responses are skipped; idle lane messages carry the native parent-message marker; and process-state test helpers retry interrupted syscalls. These are existing main changes, not new transfer implementations or new native acceptance results.

## Open defects and limits

The following owner-reported defects remain OPEN to fix. They are not accepted standard behaviour and this transfer wiring does not repair them:

- **P, interactive cancellation:** Ctrl+C can drop a peer message already steered into the running task, with no notice or reply despite an `injected` receipt.
- **W7, lane interruption:** a message accepted for a running Run can be dropped when that Run is interrupted.
- **A8a/A8b, interactive framing:** an idle peer message is framed as user-typed input, including native `@path` attachment handling; busy text says "The user sent a message while you were working". The native interjection interface does not carry an origin field. The lane parent-message correction does not fix the interactive path.

The earlier [v0.5.12 evidence and limits](v0.5.12.md#evidence) remain attributed to their recorded builds and native versions. No macOS native or full cross-version/default-policy matrix is claimed. Native updates, leader ownership and delivery remain subject to the documented [Grok lifecycle limits](../../grok/README.md).
